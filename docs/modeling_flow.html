Layer 1：目标、树学习与评价

预测对象与样本单位

对客户 i、产品 ℓ、快照 t，只有 eligᵢ,ℓ,t=1 的行进入该产品的训练与评价。标签 yᵢ,ℓ,t=1 表示在 (t, t+3个月] 内有合格购买，否则成熟标签为 0；另等 2 个月才认为标签完整，即直接计算 ready_on=t+5个月。模型估计的是该产品 eligible 客户在这个窗口内的购买倾向，输入 x 是当时的快照特征，不包含未来购买属性。

训练单位是客户×快照行，并非互相独立的购买事件：同一客户会重复出现，一次购买也可使多个快照为正。拟合行数、客户数、distinct purchase_id 三者不同；client 抽样保留客户的时间序列，不是正负样本均衡。当前 retrospective_holdout 只声称提取时可用数据上的回顾性时间留出，不能解释成历史部署回放；§5 的窗口与成熟度契约保持不变。

LightGBM 的 margin、损失和树更新

每个产品有自己的二分类 boosted-tree 模型。当前 objective=binary 且没有覆盖 LightGBM 的默认 sigmoid=1，所以原始概率 s 与 raw margin F 的关系为：

Fℓ(x) = Fℓ,0 + η Σₘ₌₁ᴹ fℓ,m(x)；sℓ(x) = sigmoid(Fℓ(x))
ℓ(y,F) = −y ln(s) − (1−y) ln(1−s)
       = ln(1+exp(F)) − yF
g = ∂ℓ/∂F = s−y；h = ∂²ℓ/∂F² = s(1−s)

f 是一棵树给当前行所属叶子的更新，η 是 learning_rate，M 是选定轮数；各轮在已有 margin 上增加修正，并非对树的概率取平均。初始项与缩放由 LightGBM 保存，不能在读取模型后再重复乘 learning_rate。二元交叉熵惩罚高信心的错误预测；梯度与 Hessian 给出当前误差的方向及局部曲率。

lambda_l2 对叶值做 L2 正则。用一个普通叶子的局部二阶近似说明其作用：若叶内 G=Σg, H=Σh，关于叶更新 w 的项为 G·w + ½(H+λ)w²，相应驻点是 w=−G/(H+λ)；更大的 λ 会压缩同样 G/H 下的更新。这是解释叶更新的局部近似，不是把 sklearn 线性模型的惩罚目标当成 LightGBM 的完整训练算法；实际还受树分裂、叶约束、采样和 shrinkage 等影响。

当前 training.yaml 为 binary_logloss、num_leaves=31、learning_rate=0.05、min_data_in_leaf=200、feature_fraction=0.8、bagging_fraction=0.8、bagging_freq=1、lambda_l2=1、最多 2000 轮、50 轮 early stopping。特征/行采样用于树训练，不是 class weights；未使用 class weights、SMOTE 或 scale_pos_weight。默认参数含义参见 LightGBM 4.6 参数。

01 在 tuning_fit 训练、inner_valid 选 best_iteration，再另建固定轮数的 champion；默认 all_train 重拟合，或按配置只用 tuning_fit，始终排除 calibration/Test。关闭校准也不会取消这个 Train 内 refit。类别水平分别从各模型的实际拟合人口学习；未知类别编码为 NaN，数值为 float32。inner_valid 已参与轮数选择，其指标是 tuning 诊断，不是无偏最终成绩。logistic baseline 使用自己的 fit-only 预处理，只作比较；更优时 WARN，绝不自动换掉 champion。

指标各回答什么问题

在固定某一产品的 eligible 评价行上，p 表示本次评价的实际概率字段（raw 或真实 calibrated）。AUROC 衡量正例是否排在负例之前，lift 衡量高分人群的正例集中度；O/E、Brier 与 log-loss 检查概率刻度，而不是只看名次：

AUROC = P(p⁺ > p⁻) + ½ P(p⁺ = p⁻)
k = ceil(0.10 n)
lift@10% = [Σ(前 k 行的 y)/k] / [Σy/n]
O/E = Σy / Σp
Brier = (1/n) Σ(p−y)²
log-loss = −(1/n) Σ[y ln(p)+(1−y) ln(1−p)]

AUROC 需要同时有正、负例；只有一类时不能赋一个有意义的 AUROC。lift 先按 p 降序，同分保留评价行顺序，分母正例率必须非零；这与跨产品排名按 l2 名字典序平分是不同规则。O/E>1 表示该批观测正例数多于预测总和（整体低估），O/E<1 表示整体高估，但 O/E≈1 本身不能证明每个概率区间都准确。Brier 和 log-loss 越低越好；实际 log-loss 以 1e-15 裁剪端点避免 log(0)。重复客户的依赖也解释了为何现有 CI 按 client 聚类 bootstrap，不能将每行视为独立购买。

数学示例，非模型成绩：十行已按概率降序排列，p=[0.90,0.80,0.70,0.60,0.50,0.40,0.30,0.20,0.10,0.05]，y=[1,0,1,0,0,1,0,0,0,0]。正负例配对共 3×7=21 对，正例胜出 17 对且无并列，所以 AUROC=17/21=0.809524。top 10% 取 ceil(1)=1 行，命中率 1，整体率 0.3，lift=3.333333；Σp=4.55、Σy=3，O/E=0.659341，Brier=0.185250，log-loss=0.533367。这个例子能把正例排得较前，却总体高估概率；排序好不等于校准好。

评价中的 calibration slope 是在所评价块上另拟合诊断回归 P(y=1)=sigmoid(α+β·logit(clip(p,1e-6,1−1e-6)))，实现为 LogisticRegression(penalty=None)，报告 β 和 α；理想刻度参照 β≈1、α≈0。它不更新服务模型，也不利用 Test 选择校准器。这个无惩罚诊断不能与 §8.1 在独立 calibration 块拟合、带弱 L2 的 Platt 参数 a,b 混同；单类或退化输入也会使诊断无定义或不稳定。

概率如何变成 Top-3

先确定该客户的 eligibility 与产品 tier/gate 放行集合，再在集合中计算 ranking_scoreᵢ,ℓ = selected_probabilityᵢ,ℓ × business_weightℓ，降序取 Top-3，同分按 l2 名字典序。权重表达业务排序策略；这个乘积不是已建模的期望收入，也不是联系客户后的因果增益。不同产品的概率可比性仍需验证；Layer 2 的属性指导是在选中之后生成，不回头重排产品。

校准改的是概率刻度，排序要分两种看

每个产品学习自己的变换。s 是冻结 champion 的原始分数，q 是实际进入公式的裁剪值，y∈{0,1} 是成熟购买标签。下面参数与数字均为数学示例，不是模型拟合结果或验收成绩。

1 · odds、logit 与 sigmoid 是什么？

ε = 10⁻⁶
q = clip(s, ε, 1−ε) = min(max(s, ε), 1−ε)
odds(q) = q / (1−q)
logit(q) = ln(q / (1−q))
sigmoid(z) = 1 / (1+exp(−z))
sigmoid(logit(q)) = q
logit(sigmoid(z)) = z

odds 是“发生概率 / 不发生概率”：10% 的 odds 是 1/9，50% 的 odds 是 1。logit 将概率变到实数轴，sigmoid 在精确运算中做逆变换。裁剪避免 0/1 的无限 logit；q 可能不同于 s，裁剪也不修复缺失/无效输入。

2 · Intercept-only：只拟合 a

b = 1；z = a + logit(q)
p = sigmoid(z)
p/(1−p) = exp(z)
         = exp(a) · q/(1−q)
p = exp(a) · q / (1−q + exp(a) · q)

乘的是 odds，不是概率，也不是固定百分点。a=ln(2) 时 odds 翻倍：10%→18.18%，50%→66.67%。a=0 返回 q；只有未裁剪时才等于 s。

3 · Platt：同时拟合 a 与 b

z = a + b · logit(q)
p = sigmoid(z)
p/(1−p) = exp(a) · [q/(1−q)]ᵇ

a 调基准 odds：q=0.5 时 p=sigmoid(a)。b 缩放 log-odds 差值；预测公式取 b=1 就是 intercept-only，实际拟合过程仍不同。

a=0、b=0.5 时：10%→25%，50%→50%，90%→75%。本例向 50% 收缩；其他 a,b 不一定如此。

4 · 用什么数据和目标函数拟合？

只用独立 calibration 上的 eligible 冻结 champion 预测/标签，既不在 Train 拟合校准器，也不在 Final Test 优化参数或选择方法。n 是校准拟合行数，含正、负标签；E 是 distinct evidence 事件数，一次购买可以对应多个快照标签，两者不能互换。

pᵢ = sigmoid(zᵢ)
L = −(1/n) Σᵢ [yᵢ ln(pᵢ) + (1−yᵢ) ln(1−pᵢ)]
  =  (1/n) Σᵢ [ln(1+exp(zᵢ)) − yᵢ zᵢ]
稳定的每行计算：
max(zᵢ,0) + ln(1+exp(−|zᵢ|)) − yᵢ zᵢ

稳定算法避免 exp(z) 溢出。实际 intercept 固定 b=1，使用 logaddexp(0,z)−y*z 的平均值，在 (-20,20) 做有界截距搜索；不收敛或结果距边界小于 1e-6 时拒绝。

Platt 调用 LogisticRegression(C=platt_C, solver="lbfgs", max_iter=1000, tol=1e-10)，无 sample/class weights。本机已核对的 sklearn 1.6.1 默认 penalty="l2"、fit_intercept=True，目标是：

J(a,b) = L(a,b) + b²/(2nC)
截距 a 不受惩罚；默认 C=1,000,000

默认 L2 很弱，但不等于零。源码/配置中 “effectively unpenalised” 不能读作精确无正则最大似然。依据 sklearn 1.6 官方目标函数和 参数文档；尚未验证的 Databricks Runtime 仍须核对版本。

两种 fit 都需要正、负标签；单一类别会报错，不会自动变成成功的 intercept 回退。缺失所需行/块或无效分数/标签违反 02 契约。常数或几乎常数分数没有可恢复的区分信息；clip、极端参数、数值饱和可产生并列或退化诊断。这些边界说明不代表所有情形已做端到端测试。

5 · 单产品内，为什么排序可以保持？

dp/dq = p(1−p) · b · 1/[q(1−q)]
      = b p(1−p)/[q(1−q)] > 0

对内部 q∈(0,1)、有限 a 和有限正 b，精确运算下严格递增；实际浮点计算还需没有饱和。intercept 的 b=1 也满足。但这不是对原始 s 的无条件严格单调保证：不同 s 可 clip 到同一 q，sigmoid 数值饱和也会增加并列。

固定同一产品的评价行与标签，如果所有两两大小关系和并列都相同，AUROC 就相同，因为它只取决于正负例的胜负与并列；平分处理相同时，top-fraction 顺序和集合也相同。新增并列时不能无条件保证。02 另检查实际 Test Spearman ρ≥1−1e-9；常数序列的未定义相关等退化可被拒绝，这不证明概率准确。

6 · 同一客户跨产品，Top-3 为什么仍会改变？

四个虚构产品都满足同样资格，集合固定，业务权重均 W=1；每个变换均为 b=1 的递增函数，只是各产品 a 不同：

产品原始 s=q截距 a校准 p顺位变化
A40%ln(1/4)14.29%1→4
B30%ln(2)46.15%2→1
C20%020.00%3→3
D10%ln(4)30.77%4→2

raw 顺序 A→B→C→D，校准后 B→D→C→A；Top-3 从 {A,B,C} 换成 {B,D,C}。各产品内客户排序保持，与该客户跨产品顺序改变可以同时成立。例子只证明顺序和成员可以改变，不保证推荐收益或校准质量改善。

跨产品 calibrated 概率的准确性和可比性需要一致目标/数据及实际验证，不能仅靠单调性证明；raw 也没有这项保证。实际 gate、eligibility、业务权重和图 4 的平分规则保持原契约。

验证到哪里：最近 10% 合成 calibrated 验收为三个 limited/intercept、其余 insufficient；raw 路径已测试。当前 full-volume own/Platt 端到端未运行，既有全量指标是历史记录。数学示例检查仅验证本文数字，不是新的模型、流水线或 Databricks 验收。

Layer 2：购买条件下的属性分布

目标与 head 的训练人口

Layer 1 回答“会不会买这个产品”，Layer 2 使用 eligible 购买事件与对应快照特征，学习 P(A=v | 已购买产品 ℓ, x, eligible) 这种购买者条件下的属性选择模式。未购买行不是 Layer 2 的负例；这个分布不是又一份购买概率，也不估计 P(购买且选择某配置)。把购买者中的相关模式用于当前客户指导，不等于预测改变配置后的购买收益。

sp_rp / par_nonpar / buying_for 各有一个跨产品 pooled LightGBM head，输入原特征加 categorical l2。配置顺序明确为 sp_rp=[SP,RP]、par_nonpar=[Par,NonPar]、buying_for=[self,spouse,child,parent]。二分类的正类是第二个配置值，即 RP 或 NonPar；模型输出 r 后组装 [1−r,r]。前两者用 binary BCE，四值 buying_for 使用 multiclass softmax 与类别交叉熵：

二值：r = sigmoid(F(x,ℓ))；L = −mean[y ln(r)+(1−y) ln(1−r)]
多值：r_v = exp(F_v) / Σ_u exp(F_u)
      L = −(1/n) Σᵢ Σ_v 1[Aᵢ=v] ln(rᵢ,v)

训练池包含该属性有至少两个有效值的所有 L2 的有效 Train 购买行，即使某 L2 最终使用 share，仍可为 pooled head 提供训练行。head 在这个训练池最后 3 个实际观测申请月上 early-stop，再以选定轮数在完整 pooled Train 重拟合。Layer 2 类别字典来自自己的 pooled Train；它有独立的申请日期 Train/Test（当前 Train≤2026-01-31，Test 2026-02-01..07-31），不复制 L1 的留出窗口，也没有实现 Layer 2 calibrator。

逐产品决定 head、share、fixed、rule

服务计划再按 L2 检查该属性的有效值：单一值为 fixed；多个值时，head 需每个有效值至少 200 条有效 Train 购买行，否则使用 Laplace 历史占比。这里 min_rows_per_value=200 是属性样本条件，与 L1 校准 own tier 的 200 个 distinct evidence 事件是两回事。若产品无有效值，则为 not_applicable。

对 K 个有效值及计数 n_v，share 使用 r_v=(n_v+1)/(Σ有效值 n_u+K)，无效值为 0。这是加一平滑计数，不训练一个优化器。例如有效值计数 [8,1,0] 时得到 [9/12,2/12,1/12]=[0.750000,0.166667,0.083333]，零计数也有小的非零占比。fixed 给唯一值概率 1；mass_higher 的多值 rule 对 wealth_seg3∈{UHNW,HNW,Affluent} 给 HigherEnd，否则给 Mass，缺失也走 Mass。rule/fixed/share 都没有学习损失最小化步骤；它们仍要经过后面的有效性约束。

先 mask 再归一化，最后决定是否 abstain

每个产品的属性有效值由 validity 表按属性投影得到（未提供该属性列时使用配置值全集）；同时按客户特征施加 buying_for 约束：spouse 要 Married、parent 要年龄<50、child 要年龄>25。on_missing 决定缺失输入 allow/block，当前三条均明确 allow，含义是未知不据此排除，不表示条件已被事实验证。

令 m_v 表示产品有效性与客户约束都允许该值。对有限概率，服务变换是：

r′_v = m_v r_v / Σ_u(m_u r_u)
margin = 最大 r′ − 第二大 r′

实际实现用 np.where(mask, r, 0) 清零后才求和：被 mask 排除的 NaN 可以被移除，并非输入任意一项 NaN 都必定使整行无效。保留下来的总量为 0 或非有限时输出 not_applicable；总量可用时归一化。head/share 的 margin<0.20 才 abstain；相等的 0.20 按规则通过（浮点计算按实际存储值比较），fixed/rule 不受 margin abstain。只剩一个非零值时归一化为 1、其余为 0，margin=1；并列最大值先按配置值顺序选取，再判断 abstain。

例如 buying_for 的原概率按配置顺序为 [0.45,0.35,0.15,0.05]，当前客户允许 self/child、不允许 spouse/parent，mask=[1,0,1,0]。保留总量为 0.60，归一化为 [0.75,0,0.25,0]，margin=0.50，输出 self。另一个有限分布 [0.45,0.40,0.10,0.05] 若全部允许，margin=0.05，head/share 应 abstain；前述三值 share 示例若均允许，margin=0.750000−0.166667=0.583333，通过。这些都是纯数学示例，不是实测 head 概率。

当前按每个属性独立给指导；把各 head 的概率直接相乘不等于学到了有效联合配置，更不能证明该组合最优。validity 的属性投影也不是联合组合求解器。04 在产品 Top-3 确定后才计算指导，不据此重排产品。属性选择、购买概率和因果收益应分别解读。

实现对应：03 的 l2_plan / train_head、modeling.py 的 class_probabilities / restrict_probabilities / layer2_guidance、layer2.yaml、validity。同义入口：英文、离线图解。

数学说明 · 当前实现

SHAP：校准前 log-odds 的贡献

实际调用、baseline 与单位

当前 modeling.feature_contributions 调用的是原生 LightGBM Booster.predict(X, pred_contrib=True)。二分类返回 n×(d+1)：前 d 列对应原始模型特征贡献，末列是 Booster 返回的 bias。helper 检查形状后只把前 d 列交给 reasons；bias 仍是理解完整分解所必需的基准。这里没有构造 shap.TreeExplainer、用户 background DataFrame、interventional background、probability/logloss 的 model_output，或 Layer 2 explainer。

原生 TreeSHAP 使用模型树中保存的路径/计数信息处理特征贡献，依据 LightGBM 4.6 Booster.predict 文档与 官方 tree.h 实现。不能把没有传入的“总体平均客户”、当前打分批次或用户选定客户群说成这个调用的 background。末列 φ₀ 是该模型的 raw-output baseline，不是平均购买概率，也不是约定为 0。

对当前默认 sigmoid=1 的 L1 二分类 champion，完整加法分解在 raw log-odds（margin）尺度成立：

Fℓ(x) = φ₀,ℓ + Σⱼ φⱼ,ℓ(x)
sℓ(x) = sigmoid(Fℓ(x))

正贡献把 margin 向上推，负贡献把它向下推。纯数学瀑布例子为 −2.0 → +0.6 → +0.3 → −0.1：F=−2+0.6+0.3−0.1=−1.2，s=sigmoid(−1.2)=23.15%。其中 +0.3 是 log-odds 贡献，绝非 +30 个百分点；sigmoid 非线性意味着概率增量依赖已有 margin，不能逐项 sigmoid 后相加。各产品有各自模型和 bias，跨产品 SHAP 数字不能当成概率收益比较。

解释输入严格沿用对应 champion 的 feature_columns 顺序、已保存类别水平与 float32 数值；未知类别为 NaN。贡献对应 LightGBM 的原始输入特征，不是 logistic baseline 的 one-hot 列。03 既有 smoke 从 Test 购买行取最多 100 行，检查“特征贡献和+bias”对 raw_score=True 的最大误差<1e-6；这里只描述已有实现与既有流水线覆盖，本次没有再跑 smoke/训练。

从完整贡献到可展示理由

reason_group 的聚合是 Φ_g=Σⱼ∈g φⱼ。推荐理由只保留 Φ_g>0、explainable 且非 sensitive 的组，降序取 top_n_reasons（默认 3），同分按配置组顺序。正贡献组的代表特征取组内最大正方向贡献；完整审计中负组则取最负方向特征。代表特征仅用于展示，不能代替全组和。

审计表可保留所有组及 sensitive/explainable 标志，可选记录 feature contributions；对外正向前三理由省略 bias、负组和被过滤组，不是完整可加分解。没有展示某负组不表示该特征未被模型使用；分组只是业务展示映射，不是特征独立性或理论独立性的保证，也不授权展示原本被过滤的敏感属性。

校准之后，这些贡献还能说明什么

当前返回的解释只分解校准前的 L1 champion。它不分解 calibrated probability、business_weight、eligibility/gate、跨产品 rank、Layer 2 head/rule 或属性选择；不能把 reason_1..3 描述为完整的“为何 Top-3”证明。校准保留单产品内部客户次序，也不能补上这些未解释环节，而且各产品的变换不同，可能改变客户的跨产品次序。

若完全没有 clipping 改变输入且没有数值饱和，可作下列代数推导：

logit(p) = a+bF = (a+bφ₀) + Σⱼ bφⱼ

这是 logit 尺度的仿射变换，未实现为当前解释输出；不能据此宣称已计算 calibrated-probability SHAP。再经 sigmoid 后，特征的概率贡献不满足这种逐项相加关系；发生 clip 时也不能直接把 logit(q) 替换成 F。

SHAP 在既定模型与贡献分配假设下解释关联和模型归因，不证明因果、行动建议、改变一个特征就能获得相应收益，或反事实保证。相关特征及 background/路径分配假设会影响功劳如何分摊；此实现没有提供特征独立、因果识别或公平性保证。

实现对应：modeling.py 的 feature_contributions / group_contributions / explain_rows、03 的加法检查、04、reason_groups.yaml、feature_groups.csv。同义入口：英文、离线图解。
